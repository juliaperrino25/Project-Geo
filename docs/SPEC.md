# World Map Quiz — module interface spec

A Seterra-style "click on the country" quiz on a world map, playable against
two historical snapshots — **1 January 1914** and **1 January 1940** —
switched with a toggle in the UI. Static site: plain HTML/CSS/JS, **no build
step, no frameworks, no ES modules** (must work when `index.html` is opened
directly via `file://` as well as over HTTP). Every JS file is a classic
script that attaches one global (`window.GEOMAPS`, `window.GeoMap`,
`window.GeoGame`, `window.GeoApp`). Node tests load the game module via
`require`, so game.js must also do
`if (typeof module !== 'undefined') module.exports = GeoGame;`.

Load order in index.html — every snapshot's data loads before either notes
file, and all data loads before the app scripts that read it:

```html
<link rel="stylesheet" href="css/style.css">
<script src="data/world1914.js"></script>
<script src="data/world1940.js"></script>
<script src="data/notes1914.js"></script>
<script src="data/notes1940.js"></script>
<script src="js/map.js"></script>
<script src="js/game.js"></script>
<script src="js/app.js"></script>
```

## 1. Data: `data/world<year>.js` → `window.GEOMAPS`

Generated by `tools/build_data.py` (do not hand-edit), one file per snapshot
year. This replaces the single `window.WORLD1940` global from the one-map
version of this spec — **that global no longer exists**; every snapshot now
lives under one shared registry, keyed by year id:

```js
window.GEOMAPS = window.GEOMAPS || {};
window.GEOMAPS["1940"] = {
  meta: {
    id: "1940",                    // matches the GEOMAPS key and the year-toggle button's data-year
    year: 1940,                    // numeric year, used to sort GeoApp.years() ascending
    label: "1940",                 // short label shown on the year-toggle button
    title: "World, 1 January 1940",
    date: "1940-01-01",
    width: 1000, height: 438,      // viewBox size; both current snapshots agree, but read it
                                    // per snapshot — don't assume it's fixed across years
    projection: "Natural Earth",
    sources: ["..."]                 // attribution strings
  },
  regions: [                         // for the region selector; "world" = all
    { id: "world",    name: "World" },
    { id: "europe",   name: "Europe", bbox: [434.4, 28.2, 618.1, 143] }, // optional view box (viewBox units)
                                     // used by map.zoomToRegion instead of the union of entity bboxes
    { id: "asia",     name: "Asia & Middle East" },
    { id: "africa",   name: "Africa" },
    { id: "americas", name: "Americas" },
    { id: "oceania",  name: "Oceania" }
  ],
  entities: [
    {
      id: "germany",                 // unique slug *within this snapshot*, used everywhere as the key
      name: "Germany",               // display name used in the prompt
      aliases: ["German Reich"],     // optional, may be empty
      sovereign: null,               // or name of the controlling power, e.g. "United Kingdom"
      status: "sovereign",           // "sovereign" | "dependency" | "occupied" | "puppet"
      region: "europe",              // one of the region ids other than "world"
      quiz: true,                    // false = drawn on the map but never asked (microstates, specks)
      label: [512.3, 118.9],         // a point guaranteed inside the largest polygon (viewBox units)
      bbox: [498.1, 105.2, 530.4, 131.0], // [x0, y0, x1, y1] in viewBox units
      area: 152.7,                   // viewBox px², use for sizing decisions
      path: "M512.3 118.9L...Z"      // SVG path `d`, may contain several subpaths
    }
  ]
};
```

`data/world1914.js` sets `window.GEOMAPS["1914"]` the same way — same `meta` /
`regions` / `entities` shapes, its own `id`/`year`/`label`. Entity and region
object shapes are otherwise identical to the single-map version of this spec.

Notes stay a separate, per-year global rather than living inside `GEOMAPS`:
`data/notes1940.js` sets `window.NOTES1940 = { "<id>": { note, extraAliases } }`,
`data/notes1914.js` sets `window.NOTES1914` the same shape, and both are shown
by the app after each answer. Code that needs "the notes for the active year"
looks them up dynamically as `window["NOTES" + yearId]` (e.g.
`window["NOTES" + GeoApp.currentYear()]`) rather than hard-coding either name.
Coordinates in both `GEOMAPS` and notes are already projected into SVG
viewBox units (`0 0 meta.width meta.height`); no projection code is needed in
the browser.

Guarantees: within a snapshot, entity ids are unique; every `quiz: true`
entity has area ≥ ~1.5 px² so it is clickable when zoomed; `label` is inside
the shape (a click there hits it). **Entity ids are not stable across
years** — 1914 and 1940 are independent id namespaces; the same country can
have a different id (or not exist at all) from one snapshot to the other, so
never carry an id from one year's data into a lookup against the other year's.
`NOTES1914`/`NOTES1940` are keyed by that year's entity ids for the same
reason. Until the real data lands, `data/world1914.js` and `data/world1940.js`
are **stubs** with a handful of rectangles that follow this schema exactly.
Code against the schema, not the stub content.

## 2. Map renderer: `js/map.js` → `window.GeoMap`

```js
const map = GeoMap.create(containerEl, GEOMAPS["1940"], {
  onClick: (id) => {},          // entity clicked (any state); null-safe
  onHover: (idOrNull) => {}     // optional
});
map.setState(id, state);        // state: null | "correct1" | "correct2" | "correct3" | "revealed" | "wrong"
                                // removes any previous state-* class and adds `state-<state>`
map.getState(id);               // → the current state string or null
map.clearStates();              // all entities back to default
map.flash(id);                  // short visual pulse on an entity (used when revealing the answer), ~1s, CSS class "flash"
map.setHint(id);                // optional: highlight an entity outline (class "hint"); setHint(null) clears
map.zoomToBBox([x0,y0,x1,y1], padding = 0.08); // animate viewBox to fit bbox
map.zoomToRegion(regionId);     // fits region.bbox when present, else the union of entity bboxes; "world" = full extent
map.resetZoom();
map.zoomBy(factor);             // 1.5 zooms in, 1/1.5 zooms out, around the current centre
map.setInteractive(bool);       // when false, clicks are ignored (hover still ok)
map.getLabelScreenPoint(id);    // → {x, y} in *client/page* pixels for the entity's label point (used by tests)
map.destroy();
```

DOM contract (the UI/CSS and e2e tests depend on it):

```html
<div class="geomap">                       <!-- containerEl gets this class -->
  <svg class="geomap-svg" viewBox="0 0 1000 520" preserveAspectRatio="xMidYMid meet">
    <rect class="ocean" .../>
    <g class="countries">
      <path class="country" data-id="germany" d="..."></path>
      ...
    </g>
  </svg>
</div>
```

- Zoom/pan: mouse wheel zooms around the cursor, drag pans, double-click zooms in.
  Touch: pinch + drag if cheap to add. Clamp zoom between 1× and 12×.
- A drag of more than ~4px must not count as a click.
- `setState` only toggles classes; all colours live in CSS (`.country`,
  `.country:hover`, `.country.state-correct1`, `.state-correct2`,
  `.state-correct3`, `.state-revealed`, `.state-wrong`, `.country.flash`,
  `.country.hint`).
- No external libraries. Vanilla DOM + SVG only.

## 3. Game engine: `js/game.js` → `window.GeoGame` (pure logic, no DOM)

Seterra rules: the player is prompted with one entity at a time, in random
order. Clicking the right one scores it: 1st try → `correct1` (green),
2nd → `correct2` (yellow), 3rd → `correct3` (orange). After the 3rd wrong
click the answer is revealed (`revealed`, red) and the game moves on. Clicking
an entity that has already been scored/revealed is ignored (no penalty).
Score = percentage of entities answered correctly on the first try.

```js
const game = GeoGame.create({
  ids: ["germany", "france", ...],   // entity ids to ask, in any order
  maxTries: 3,                       // default 3
  shuffle: true,                     // default true
  random: Math.random,               // injectable for deterministic tests
  now: Date.now                      // injectable clock
});

game.current();      // → id currently asked, or null when finished
game.guess(id);      // → {
                     //     ignored: bool,        // true if id already answered, or game finished
                     //     correct: bool,
                     //     triesUsed: n,         // wrong clicks so far on the current prompt (after this guess)
                     //     state: "correct1"|"correct2"|"correct3"|"revealed"|"wrong"|null,
                     //                           // state to paint on the *clicked* id (`"wrong"` = brief red flash,
                     //                           // not persistent); when revealed, `revealedId` tells which id to paint red
                     //     revealedId: id|null,  // set when the 3rd wrong guess reveals the answer
                     //     finished: bool,
                     //     next: id|null         // the next prompt (== current() after the call)
                     //   }
game.stats();        // → { total, answered, remaining, firstTry, secondTry, thirdTry, revealed,
                     //     scorePercent (0-100, integer), elapsedMs }
game.results();      // → [{ id, state, triesUsed }] in prompt order (answered ones)
game.isFinished();
game.order();        // → array of ids in prompt order (frozen)
game.restart();      // same ids, new shuffle, timer reset
game.elapsedMs();    // running while unfinished, frozen at finish
```

`GeoGame.stateForTries(triesBeforeCorrect)` helper exists: 0→"correct1",
1→"correct2", 2→"correct3".

## 4. App / UI: `index.html`, `css/style.css`, `js/app.js` → `window.GeoApp`

Seterra-like layout: a top bar with the prompt (**Click on: Germany**), the
counter (`12 / 118`), a timer (`01:23`), and the score (`92%`); the map fills
the rest of the viewport; a control strip that opens with a year toggle
(`#year-toggle`, segmented buttons for each available year, default
**1940**) sitting left of a region `<select>` (populated from the active
snapshot's `regions`), then *Start / Restart*, zoom buttons, and an *Include
small territories* checkbox (adds `quiz:false` entities). When the game
finishes, show a results overlay (score, time, list of misses) with a *Play
again* button. Wrong clicks flash the clicked entity red briefly and show the
name of what was clicked in the top bar ("That was Siam"). Reveals flash + zoom
hint on the right answer.

Year toggle: `#year-toggle` contains one `button.year-btn[data-year]` per
year in `GeoApp.years()`; the button for the active year carries class
`is-active` and `aria-pressed="true"` (inactive buttons carry neither).
Clicking a year button calls `GeoApp.setYear(yearId)`.

Required DOM ids (tests rely on them): `#map`, `#prompt-name`, `#counter`,
`#timer`, `#score`, `#year-toggle` (contains the `.year-btn` buttons above),
`#region-select`, `#start-btn`, `#results` (overlay, has `hidden` attribute
when not shown), `#results-score`, `#play-again-btn`, `#include-small`,
`#feedback` (the "That was X" line).

`window.GeoApp` exposes for tests:
`{ data, map, game (current GeoGame or null), start(regionId, opts), currentId(), years(), currentYear(), setYear(yearId) }`.

- `data` — the *active* snapshot, i.e. `GEOMAPS[currentYear()]` (the `regions`
  and `entities` currently on screen). It is swapped, not mutated, when
  `setYear` runs.
- `years()` — the available year ids as strings, ascending, e.g.
  `["1914", "1940"]`.
- `currentYear()` — the active year id, e.g. `"1940"`.
- `setYear(yearId)` — switches the active snapshot: rebuilds the map from
  `GEOMAPS[yearId]` (region select repopulated from its `regions`) and
  discards any in-progress game (`game` becomes `null` — a mid-game switch
  throws away that progress with no confirmation prompt). It does **not**
  auto-start; the player presses *Start* again. Default year on load is
  `"1940"`.

Colours (Seterra-ish): ocean `#a8d3ee`, land `#f2edd8`, land hover `#e6dfbf`,
borders `#8d8d8d` 0.35px, correct1 `#4caf50`, correct2 `#ffd54f`, correct3
`#ff9800`, revealed `#e53935`, wrong flash `#e53935`. Font: system sans.

## 5. Tests

- `test/game.test.js` — `node --test` unit tests for GeoGame.
- `test/e2e.js` — Playwright (already installed globally; Chromium at
  `/opt/pw-browsers`, use `executablePath` fallback) script that serves the repo
  root over HTTP on a free port, loads `index.html`, asserts the map rendered
  every entity for the default year, starts a "world" game, and plays it to
  completion by clicking the label point of `GeoApp.currentId()` each turn (via
  `map.getLabelScreenPoint`), asserting 100% score at the end, then a second run
  that deliberately answers wrong to check reveal behaviour. It also exercises
  the year toggle — switching to each year in `GeoApp.years()` and confirming
  the map rebuilds with that year's entities and any in-progress game is
  discarded, per the `setYear` contract in section 4 — before returning to the
  default year. Saves screenshots to `test/screenshots/`. Exit code non-zero on
  failure.
